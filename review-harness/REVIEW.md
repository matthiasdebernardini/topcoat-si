**Claudius correctness, error handling, logging, and telemetry review**

Reviewed https://github.com/rescrv/claudius at commit `463c64633ecf5097f1b7c5d8e39bbd9ade7ed784` (version 0.33.0), September 21, 2026. Scope: Anthropic HTTP client, request/response types, SSE parser, stream accumulation, retry/error mapping, logging/metrics, and agent/tool integration. Telegram transport and the full shell/filesystem security boundary were outside this API-focused review.

I found 22 actionable defects. P1 means fix before relying on this in production; P2 means a concrete correctness defect to fix; P3 means a smaller defect. All production source files remain unchanged. The upstream source is preserved in `../../vendor/claudius`; all added review tests and the telemetry harness are in this directory. The logs retain the original temporary paths as historical evidence.

**Error handling, logging, and telemetry findings**

1. **P1 — Client Debug output exposes authentication secrets.** [client.rs:265–275](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/client.rs#L265-L275). Derived `Debug` includes the plaintext `api_key` and cached authentication headers. Tests with a dummy sentinel find the secret twice for Anthropic and three times for Baseten, which also adds Authorization. Logging `?client`, or adding this representation to a Sentry event, exports credentials. Implement redacted Debug and mark authentication HeaderValues sensitive; doing only one leaves the other leak. Reproduced in `review_error_debug.rs`.

2. **P1 — Truncated and failed streams can become successful final messages.** [accumulating_stream.rs:108–125](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/accumulating_stream.rs#L108-L125), [147–150](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/accumulating_stream.rs#L147-L150). `MessageStop` is ignored and errors are forwarded without retaining failure state; EOF finalizes any started message as `Ok`. A message-start plus partial text followed by EOF returns success with `stop_reason: None`. A message-start plus an error followed by EOF also finalizes successfully if the caller drains the stream. `LoggingStream` then invokes its successful-completion callback. Track terminal success/failure explicitly, require normal completion for the final-message receiver, and reserve incomplete results for `finalize_partial`. Reproduced in `review_streaming.rs` and `review_logging.rs`.

3. **P2 — Fatal SSE errors repeat forever instead of terminating.** [sse.rs:82–89](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/sse.rs#L82-L89), [112–119](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/sse.rs#L112-L119), [183–192](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/sse.rs#L183-L192). Oversized unfinished frames, incomplete UTF-8 at EOF, and the elapsed-time branch return an error with unchanged state. Every subsequent poll returns the same error immediately. Consumers that log errors and continue can spin, flood telemetry, or make `collect()` grow without bound. Enter a terminal state after unrecoverable errors. Reproduced for buffer overflow and incomplete UTF-8 in `review_streaming.rs`.

4. **P2 — LoggingStream suppresses finalization errors.** [client.rs:69–76](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/client.rs#L69-L76). The completion receiver is matched only as `Ok(Ok(message))`; `Ok(Err(error))` is silently dropped. An HTTP 200 empty SSE response becomes clean EOF to `stream_with_logger()` callers, even though accumulation reports a missing message start. Emit the finalization error as a stream item and record it as failure. This is distinct from finding 2: fixing accumulation alone still leaves this wrapper swallowing its errors. Reproduced in `review_logging.rs`.

5. **P2 — Stream error metrics omit actual API error events.** [sse.rs:94–100](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/sse.rs#L94-L100), [280–284](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/sse.rs#L280-L284). Counters run at framing time, before JSON and Anthropic event decoding. A valid SSE `error` frame carrying `overloaded_error` yields a caller-visible error but increments `claudius.stream.errors` by zero. JSON decode errors have the same gap. Client request accounting also ends after headers, so these failures do not increment its error counter. Count errors at the decoded/lifecycle boundary, once per failure. Reproduced by snapshots of the actual biometrics collector in `review_metrics.rs`.

6. **P2 — API error metadata needed for diagnosis and Sentry is discarded.** [client.rs:645–660](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/client.rs#L645-L660), [697–708](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/client.rs#L697-L708), [error.rs:428–442](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/error.rs#L428-L442). The client reads `x-request-id`, whereas Anthropic sends `request-id`; it also ignores the body's `request_id`. Specialized error variants discard original status and error type, and most cannot retain a request ID. `status_code()` returns None even for a mapped HTTP 500 or 429. HTTP 529 is additionally labeled RateLimit, losing the overload distinction. Preserve common HTTP metadata across all error kinds, read the actual header with a body fallback, and expose it consistently. A local HTTP 500 with both IDs demonstrates the missing ID in `review_client.rs`. [Anthropic error contract](https://platform.claude.com/docs/en/api/errors).

7. **P2 — Common transient transport failures bypass retries.** [client.rs:671–677](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/client.rs#L671-L677), [713–725](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/client.rs#L713-L725), [error.rs:403–415](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/error.rs#L403-L415). A connection closed before response headers is a reqwest request error, not `is_connect()`, so it becomes nonretryable HttpClient. A known HTTP 503 whose body disconnects also becomes nonretryable HttpClient before status mapping. Local servers prepared to succeed on the second attempt receive only one request. Classify transient transport errors separately from builder/configuration errors and preserve retryable status even when the error body cannot be read. Both cases reproduced in `review_client.rs`.

8. **P2 — Network timeout conversion drops the causal error chain.** [client.rs:713–733](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/client.rs#L713-L733), [error.rs:65–71](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/error.rs#L65-L71). Timeout stores only a formatted message and duration, dropping reqwest and underlying causes. The text retains flattened detail, but Sentry's source traversal and caller downcasting cannot recover it. Streaming and batch timeout conversion do likewise. Retain an optional source for network-originated timeouts. A stalled local server demonstrates `is_timeout() == true` but `source() == None` in `review_error_debug.rs`. [Sentry error-chain capture](https://docs.rs/sentry/latest/sentry/fn.capture_error.html).

9. **P2 — SSE timeout confuses consumer work with network inactivity.** [sse.rs:79–93](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/sse.rs#L79-L93). The fixed 30-second check runs before consuming already-buffered events. Reading one event, spending 31 seconds in the caller, and requesting the second buffered event returns a timeout even though both arrived in the same chunk. It then repeats forever as in finding 3. Conversely, the check does not wrap the pending network read, so it cannot itself interrupt a stalled read. Use the configured transport read timeout or time an actual pending read, not time between consumer polls. Reproduced in `review_streaming.rs`.

**Additional Anthropic API correctness findings**

10. **P2 — Streamed server-tool arguments are silently lost.** [accumulating_stream.rs:203–207](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/accumulating_stream.rs#L203-L207), [236–259](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/accumulating_stream.rs#L236-L259). `input_json_delta` is applied only to client ToolUse blocks. Anthropic's web-search stream starts a ServerToolUse block with `{}` and then emits its query in those same deltas. The final message keeps `{}`, corrupting logging and replayed conversation history. Accumulate and parse input JSON for both tool variants. Reproduced with `{"query":"weather NYC today"}` in `review_streaming.rs`; the actual output is `{}`. [Official web-search stream example](https://platform.claude.com/docs/en/build-with-claude/streaming#streaming-request-with-web-search-tool-use).

11. **P2 — Valid CRLF SSE frames are discarded.** [sse.rs:289–291](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/sse.rs#L289-L291). Framing searches only for LF/LF. CRLF/CRLF never matches, despite later code stripping carriage returns from individual lines. A complete CRLF ping produces zero events; longer streams accumulate until the buffer limit. Parse line endings before identifying blank lines, including chunk splits. This matters for compatible providers/proxies and the exported general SSE parser; I did not observe Anthropic itself emitting CRLF. Reproduced in `review_streaming.rs`. [SSE standard](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream).

12. **P2 — Replaying a web-search error drops its required type discriminator.** [web_search_tool_result_error.rs:40–46](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/types/web_search_tool_result_error.rs#L40-L46). A received `{"type":"web_search_tool_result_error","error_code":"max_uses_exceeded"}` is serialized back as `{"error_code":"max_uses_exceeded"}`. Feeding that assistant response into the next request creates malformed history. Preserve the nested discriminator during serialization. Reproduced in `review_types.rs`. [Official web-search contract](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool).

13. **P2 — A documented web-search error makes the entire response undecodable.** [web_search_tool_result_error.rs:7–22](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/types/web_search_tool_result_error.rs#L7-L22). `request_too_large` is missing from WebSearchErrorCode. Receiving that valid tool result fails deserialization of the containing Message or stream event instead of preserving the recoverable tool error. Add the supported variant. Reproduced in `review_types.rs`. [Documented web-search errors](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool).

14. **P2 — Usage iterations incorrectly require a model on ordinary entries.** [usage_iteration.rs:17–29](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/types/usage_iteration.rs#L17-L29). Ordinary `type: "message"` iteration usage can omit model or set it to null, while fallback usage requires it. The shared struct requires `Model` in both cases, so valid iteration usage prevents deserialization of the entire response. Use distinct variants or an optional model where permitted. Reproduced in `review_types.rs`. [Official SDK definition](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_message_iteration_usage.py).

15. **P2 — An arbitrary 1 MB message limit rejects valid images and documents.** [message_create_params.rs:491–503](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/types/message_create_params.rs#L491-L503). Validation measures Debug-formatted content, including base64, against 1,000,000 bytes. A valid 640×640 RGB PNG, 1,229,883 raw bytes / 1,639,844 encoded bytes, is rejected locally even though it is below Anthropic's documented image and request limits. No caller override exists. Validate actual protocol limits or make optional application limits configurable; do not measure Debug output. Reproduced using the valid PNG fixture in `review_types.rs`. [Image limits](https://platform.claude.com/docs/en/build-with-claude/vision), [request limits](https://platform.claude.com/docs/en/api/errors#request-size-limits).

16. **P2 — Zero-token cache prewarming is rejected.** [message_create_params.rs:454–459](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/types/message_create_params.rs#L454-L459). `max_tokens: 0` is now a supported ordinary Messages API request for prewarming the cache without generating output, but validation rejects it before sending. 17. **P2 — Valid Bash restart input never reaches the callback.** [agent.rs:211–227](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/agent.rs#L211-L227). 18. **P2 — Text-editor view rejects the end-of-file sentinel.** [agent.rs:2209–2214](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/agent.rs#L2209-L2214). `view_range: Option<(u32,u32)>` cannot deserialize the documented `[2,-1]` request to view through EOF. 19. **P2 — A completed response disappears when its input costs exhaust the budget.** [agent.rs:2996–3003](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/agent.rs#L2996-L3003). 20. **P2 — pause_turn continuations bypass budget guards.** [agent.rs:2954–2958](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/agent.rs#L2954-L2958), [3057–3058](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/agent.rs#L3057-L3058). 21. **P3 — Custom-document source serialization emits duplicate type keys.** [content_block_source_param.rs:7–8](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/types/content_block_source_param.rs#L7-L8), [document_block.rs:20–22](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/types/document_block.rs#L20-L22). 22. **P3 — PDF citation page helpers treat an exclusive endpoint as inclusive.** [citation_page_location.rs:43–50](https://github.com/rescrv/claudius/blob/463c64633ecf5097f1b7c5d8e39bbd9ade7ed784/src/types/citation_page_location.rs#L43-L50). **OTLP/OpenTelemetry and Sentry verification**

Native instrumentation is biometrics counters/moments plus a custom ClientLogger. There are no library-owned tracing spans, an OTLP exporter, or automatic Sentry capture. ClientLogger has no failure or retry hook, and ordinary send/stream and Agent paths do not automatically opt into its logging wrappers. This is an integration gap relative to the requested operational behavior, not evidence that standard Rust errors cannot be used with these SDKs.

An isolated harness now included in `src/lib.rs` of this review harness uses Sentry 0.49.3 and OpenTelemetry API/SDK/OTLP 0.33.0. All four tests passed:

| Check | Result |
| --- | --- |
| sentry::capture_error on a Claudius connection error with an I/O source | Captures an event containing both exception-chain entries |
| API error capture | Captures the error, but request ID/status/type are not automatically added as structured API metadata |
| Configured OTel provider with an uninstrumented Claudius validation failure | No spans emitted |
| Explicit record_error + error status + OTLP/HTTP JSON export | A local HTTP receiver receives a span with exception event and error status |

This establishes basic manual interoperability. It does not establish automatic instrumentation, trace/Sentry correlation across asynchronous tasks, live Sentry ingestion, or operation against a production collector. Those require application configuration and additional integration work. OpenTelemetry record_error does not itself set error status; the harness does both explicitly. [OTel Span contract](https://docs.rs/opentelemetry/latest/opentelemetry/trace/trait.Span.html), [OTLP exporter](https://docs.rs/opentelemetry-otlp/latest/opentelemetry_otlp/).

Recommended implementation order: redact credentials; establish one reliable stream completion/failure lifecycle; preserve common error metadata and causes; fix retry classification and error metrics; add subscriber-based structured instrumentation that retains the active application trace context. Let the application own exporters and Sentry initialization. Record final failures once, keep retries separately observable, attach safe operation/model/request metadata, and make prompt/tool-content logging explicit. Test cancellation, retries, malformed streams, and concurrent requests with in-memory Sentry transport and a local OTLP receiver.

Two additional timing semantics need clarification if bridging existing metrics: client streaming request duration ends at HTTP headers, not at stream completion, while STREAM_TTFB begins after headers and therefore excludes request-to-header latency. Current names should not be presented as full request duration or end-to-end time to first byte without changes.
